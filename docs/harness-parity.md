## Released reference observations

The official macOS arm64 T3 Code v0.1.11 CLI artifact ran on loopback with an isolated application data directory and telemetry disabled. Its SHA-256 matched the GitHub release asset. Chromium and WebKit exercised the real pairing boundary using an ephemeral credential generated by the reference CLI.

- A fresh web connection presents a pairing form. Desktop-managed mode asks for the desktop app or an explicitly issued bootstrap credential. Web mode offers a one-time pairing token.
- After pairing, the welcome flow groups providers and projects. The captured signed-out Claude row offered Sign in, and the incompatible Codex row offered Update. Both are distinct from a connected provider.
- The 390px project decision screen exposes Add project and Start without a project together. Harness offers both choices. Registered folders use an explicit trust step, and projectless sessions create a separate scratch folder on the host when first used.

This reference run verifies pairing and welcome behavior. It used local browser viewports and remains separate from actual T3 Code desktop, native phone, and live provider evidence. Local screenshots include the test host display name and are excluded from the committed evidence.

## Named provider accounts on the host

Run `./buddy migrate` before adding accounts to a database that predates provider settings. Use `./buddy profiles:list` to get your profile ID. Add a Claude config directory or Codex session home and select the account in the composer of a project in that profile.

```sh
./buddy harness:provider-add PROFILE_ID claude 'Claude Work' --home '~/.claude-work'
./buddy harness:provider-list PROFILE_ID
./buddy harness:provider-auth WORKSPACE_ID ACCOUNT_ID
./buddy harness:run 'Reply with ok' --path PROJECT_PATH --driver claude --provider-instance ACCOUNT_ID
```

The auth command opens the provider's own login in the host terminal. It uses the same configured binary and account directory as Harness. `--logout` signs out that provider account. `./buddy harness:provider-remove PROFILE_ID ACCOUNT_ID` removes the Harness configuration. Sessions that selected the removed account report it as unavailable.

The managed ChatGPT preview opens account consent in the system browser on a macOS or Linux Harness host. Select the resulting ChatGPT plan account in the composer of a trusted project in the same profile. Re-run the connect command with the same name to sign in again. The separate Codex CLI account continues to use its own provider login.

```sh
./buddy harness:provider-chatgpt-connect PROFILE_ID 'ChatGPT Work'
./buddy harness:provider-chatgpt-disconnect PROFILE_ID ACCOUNT_ID
```
